GearBeacon V1.4 — START HERE
============================

Requirements
------------
Node.js 22.13 or newer.

Quick demo (no live store traffic)
----------------------------------
Windows: double-click run-mock-windows.bat
Mac/Linux: ./run-mock-mac-linux.sh

Then open http://localhost:8787

Live monitor
------------
Windows: double-click run-windows.bat
Mac/Linux: ./run-mac-linux.sh

What's new in V1.4
------------------
- GitHub Releases now power Check for updates.
- Server-side Expo push can alert a registered phone when the app is closed.
- Settings has per-event notification controls and Send test notification.
- Monitor health guards reject suspicious partial catalog responses.
- Failed checks back off automatically and expose health/readiness endpoints.
- Docker/Docker Compose can run one always-on centralized GearBeacon monitor.
- GitHub Actions CI/release workflows are included for the project repo.

Upgrade safety
--------------
V1.4 preserves V1.3's external SQLite database. On the first V1.4 start over a
V1.3 database, GearBeacon creates a pre-update backup and migrates schema v2 to v3.
Your watched products remain outside the application folder.

Settings
--------
Open Settings for:
- GearBeacon version / GitHub update checks
- Notification event preferences
- Test notification
- SQLite schema / data path
- Create backup now
- Export / Import

Real phone push
---------------
Configure mobile/app.json with your Expo EAS projectId, create an EAS development
or release build, then choose "Register this device for push" in mobile Settings.

Cloud monitor
-------------
docker compose up -d --build

V1.4 is still single-watchlist and unauthenticated. Do not expose port 8787
straight to the public internet; use a private network/VPN/authenticated proxy.

Automated verification
----------------------
node --no-warnings scripts/self-test.mjs

See README.md for all configuration, GitHub release workflow, mobile push setup,
health endpoints, and deployment details.
